# How I organise my Claude threads

*Pranav Garg, cofounder of Kolo. Posted on [LinkedIn](https://www.linkedin.com/in/pranav6082/) on 28 October 2026.*

100% of my product work now is through AI chat window - Claude desktop and mobile app. One of the very high impact things which evolved is how I organised Claude threads.

Product work has only one goal: make the product a success. So the threads have to be organised around that goal, as directly as possible.

It went like this:

independent threads sorted by last active (the default) → threads by function → threads by project, with a control room and child threads.

First, every thread was independent. Sidebar sorted them by when they were last active. I kept going back to find which one was doing what. I was monitoring and managing threads all day, pushing every piece of work along myself.

Second, with Grokbot, one thread could seamlessly start, run and manage other threads. So I set up bots like a team: a finance bot, a dev bot and a product bot, with a control bot over them as chief of staff. Virtual employees, more or less. It seemed the obvious way, because that’s how product teams have always been organised. It didn’t work

Work doesn’t split by function. Take one project: getting people to subscribe in app. It touches app, web pages, backend, analytics, internal tools the team uses, its accounting and marketing. No single bot owned it. Every piece needed two or three of them.

Third, and current: threads by project. On the left I now have projects: the AI advisor, subscriptions, bookkeeping and a few more. Each has one thread I talk to, the control room.

It doesn’t do the work. It starts child threads for each piece, because five, six or seven things can be in flight at once, and I don’t open those. I don’t have to watch them.

Work is grouped by project, because that’s where the goal is. A function bot can be busy all day while the project doesn’t move. A project thread is judged on one thing: did the project get closer to the goal.
